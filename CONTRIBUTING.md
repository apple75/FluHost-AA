# Contributing

Contributions should fit the [research scope](RESEARCH_SCOPE.md) and preserve the existing architecture. Open an issue or proposal describing the intended change, affected files, evidence, and validation plan before changing governed scientific parameters. Such changes require PI review and a contract update before implementation; do not edit contracts as a convenience for code changes.

For documentation or code contributions, keep changes focused, document assumptions, add meaningful tests when behavior changes, and distinguish static review from Kaggle runtime validation. Formal reproduction uses a fixed Git commit or release tag and frozen dataset provenance. See [reproducibility](docs/reproducibility.md).

Do not submit large raw FASTA files, restricted datasets, credentials, personal information, confidential material, or experimental protocols. Report missing historical information as `UNKNOWN` or `TBD`, and describe results as statistical associations unless stronger claims have explicit cited support.
